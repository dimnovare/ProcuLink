# ProcuLink Product Truth Audit — 2026-08-06 (v2)

Run the day the v1 master plan completed. **Audited:** BE `origin/main` `5db0b05` · FE `origin/main` `68ed5f2`,
both green, zero open PRs at start.

**Method:** seven parallel read-only tracks, several of which fanned out further, against the same
frame as `AUDIT-2026-07-27.md`. Evidence classes as before — `[verified]` reproduced first-hand,
`[unverified]` single-source. Each track was told what **not** to re-derive (the v1 §11 killed
findings, the 2026-08-06 session log, the production-pass "Not findings" section) so effort went to
unexamined ground.

**Deliberate difference from v1:** every track was given the v1 post-mortem's citation rules — a
citation is two assertions and they fail independently; read the anchor rather than writing the line
from memory; range *ends* were wrong fourteen times where starts were right; count fixtures rather
than estimating them. Anchor accuracy in this pass is materially better as a result.

---

## 1. Executive verdict

**The engine is now genuinely good. The product still misleads operators — but the lies moved.**

v1's charge was *"the engine is good, the product is not coherent"*, and it named three navigation
surfaces wired to nothing. All three were deleted. The v1 #1 problem — a designed output that could
not survive to order #2 — is fixed and proven by a byte-equality test.

What v2 finds instead:

- **Wiring with no screen.** A versioned draft-mapping editor, a per-supplier auto-send flag, two
  ops routes, and several documented recovery endpoints exist and have no way in.
- **Screens that render the wrong thing from correct data.** The delivery log labels every failure a
  success. The send-confirmation dialog names the wrong output format at the moment of consent. Three
  headline dashboard numbers contradict a sibling number on the same screen.
- **Claims that survived the purge by living outside the marketing directory.** The Peppol BIS 3
  claim was withdrawn from the website and is still stamped into every emitted UBL document.

**Sellable to a design partner. Not yet to a self-service buyer** — for different reasons than v1.
The reasons are now smaller, more numerous, and concentrated in surfaces rather than in the engine.

## 3. The structural finding

**Every guard this repo builds is written from the shape of the defect that prompted it, and is
therefore blind to that defect approaching from the other side.** Four independent instances, each
`[verified]`:

| Guard | Written to catch | Blind to |
|---|---|---|
| `orderCountParity.test.tsx:275` | "Ready to send" summing two statuses — it is *named* for this | Counts that do not carry `[data-count-label]`. The live defect is on the same screen |
| `route-reachability.test.ts:437` | Routes with no inbound link | Credits `HUB_TABS` entries raw, including `hidden: true` ones the strip never renders |
| `WorkerHealthAlertJobWiringTests.cs:146` | The alert sink being unregistered | Its regex stops at the constructor name; deleting the email sink argument leaves it green |
| `backendMirror.test.ts:230` | Status-manifest drift from the backend | **Has never run.** `skipIf(!BACKEND)`, and FE CI never checks out the backend |

Two more of the same family: the backend orphan guard covers `DbSet`s and the frontend route guard
covers routes, so **an API endpoint with no caller is invisible to both** — two documented recovery
doors have zero callers. And `gatedCapabilityClaims.test.ts` scans the marketing directories only, so
a capability claim that moves into `src/components/bridge/` escapes it entirely.

**The rule this earns:** a guard must be tested against the defect *class*, not the defect instance —
and the cheapest way to find its blind side is to ask which direction the next instance would come
from.

### P1 — trust, silence, or data corruption

- **`XlsxOrderParser.cs:150` reads `"73,22"` as `7322`** — a hundredfold price error, on the one parser that never sets `NeedsReview`. Three sibling locale defects alongside it, all four unfixed by any of the 41 packets.
- **WP-37 can go silent four independent ways, none of which alerts** — a wiring guard that cannot see inside what it guards; probe failure degrading to all-clear *and logging "healthy"*; that error's only destination possibly unconfigured; and an unguarded snapshot read that runs first and can kill all five conditions on one timeout.
- **The entire ingest and transform half of the pipeline cannot raise an alert.** The snapshot counts two delivery statuses. A mass parse failure is total silence — and the signals already exist on the org-scoped health page.
- **Inbound email: one global non-rotating token, accepted from the query string, and the caller picks the tenant** by a public slug with 4 hex characters of randomness.
- **No RBAC anywhere.** Any authenticated member can redirect a supplier's deliveries, mint an unattributable API key, cancel the subscription (which stops every ingest path), or forge a delivery record.
- **The send-confirmation dialog names the wrong output format** after a re-process — misleading consent on an irreversible action.
- **`/bridge` prints "Ready to send" over two different numbers**, and the attention strip and "Needs you" badge count different sets over different populations.
- **Inbox column sort is client-side over one 25-row page**; the backend accepts no sort parameter, so the "Overdue" health tile shows the 25 *newest* orders sorted oldest-first.
- **Structured parsers fill 5 of ~24 canonical fields.** Ship-to, bill-to, contacts, incoterms, totals and requested delivery date populate **only** on the AI path — a cXML `DeliverTo` present in this repo's own fixtures never reaches the database.
- **The versioned draft-mapping editor is behind a URL nothing links to.**
- **cXML sold as "Supported" on six surfaces and gated at Operations**; ERP connectors presented as an ordinary channel and gated at Enterprise; "Pilot is enough for everything here" heading a guide whose first two choices Pilot cannot make.

## 5. Refuted or corrected during the pass — do not re-open

- **The practice order does not 404.** WP-27/WP-39 rebuilt it as *email the finished file to
  yourself* (`SampleOrderService.cs:219-281`, `PracticeDeliveryState.cs:25-43`). **Do not build the
  echo endpoint** in `docs/design-system/practice-order-ending.md` — the shipped design is better:
  real delivery, real attempt row, no new infrastructure, and the user's own inbox is a more honest
  recipient than a ProcuLink-owned one.
- **SFTP overwrite defaults ON, deliberately** — at-least-once delivery means a re-drive must repair
  its own truncated file. WP-20's actual fix was the filename qualifier.
- **The WP-14 write-side duplicate-mapping regression never shipped** — caught in review before the
  squash, proven by `git log -S`.
- **`LaneDrawer`'s `MOCK_CROSSINGS` is now gated**; the note claiming otherwise is stale.
- **WP-33 did not touch `StrandedReadyOrderDetectionService`** — only WP-35 did.
- The `TOTAL_STEPS = 2` / three-panel wizard renders correctly; naming smell, not a defect.

# ProcuLink Product Truth Audit — 2026-08-13 (v3)

Run the evening all five of v2's waves closed. **Audited:** BE `main` `7018f4c4` · FE `main` `741b219`,
both green, zero open PRs, **both repositories now PRIVATE**. Backend history was rewritten and
force-pushed today, so no backend SHA older than 2026-08-13 resolves; none is cited.

**Method:** eight parallel read-only tracks, plus direct verification by the lead of every headline
finding before it was written down. Deliberately **not** v2's lens — v2's structural charge
("every guard is blind to its own defect rotated") was largely repaired today, and re-running it
would have rediscovered its own repairs. The question this pass asked instead:

> **Which claims have no verification path?** For each: the claim as the user reads it, the code
> that produces it, and what — if anything — could falsify it.

Citation discipline unchanged from v2: a citation is two independent assertions and they fail
independently. Every `file:line` below was re-read at the anchor. One of my own re-reads produced a
**wrong refutation**, caught by a later track and recorded in §4 — the trap generalises past line
numbers and is worth reading.

---

## 1. Executive verdict

**The data is now consistent. The sentences wrapped around it are not.**

v2 found nine hand-typed copies of one status vocabulary and three dashboard numbers contradicting
their siblings. Today's answer to that was excellent and it worked: `orderStatusManifest`,
`auditActionManifest`, `invoiceStatusManifest`, `deliveryAttemptManifest`, `orderCountContract`,
`gatedCapabilities ⇄ PlanConstants`, an IL scanner for billing gates, an endpoint-reachability
scanner, and `backendMirror` finally executing in CI against a real backend checkout. Drift between
two representations of the same fact is now genuinely hard to introduce.

**That fix moved the defect one layer out.** The value a surface prints is now right nearly
everywhere. What is wrong is *which* value a surface chooses, and *what word* it wraps around it —
and no registry diff can see either. Most of this audit's findings are a correct number or a correct
boolean rendered under a sentence that claims far more than the computation supports:

- a read-only pre-flight check renders a badge that literally reads **"Delivered"**
- *"every required field is filled and checked"* renders over a validation call that is **never made**
- the pre-publish impact preview says **"safe to go live"** when the revision produced *no output at all*
- a supplier that rejected **every** order scores **100%** on "Delivery success rate, last 30 days"
- the order passport says **"Accepted · Acknowledged by supplier"**, timestamped with our own clock
- the live output preview prints a green **"Valid"** for formats that have no validator
- a saved deterministic mapping is presented as **"AI confidence 95%"**, in the violet reserved for AI
- the €149 card sells **"validation"**; per-supplier validation rules refuse below €2,500/mo
- the cross-format field reference is transcribed from a document deleted six weeks ago
- one settings tab prints the raw string `email_ingestion_requires_growth` at the customer, in red

The engine did not regress. **Every one of those is a presentation-layer assertion about something
the presentation layer did not compute.**

**Still sellable to a design partner. Still not to a self-service buyer** — but the reason has
narrowed again. v1: the engine. v2: the screens. v3: **the sentences on the screens, and only where
the sentence asserts something outside the code.**

## 2. The structural finding

**Every guard in these two repositories verifies code against code. Not one verifies a claim
against anything that is not code — not a standard, not a counterparty, not a document, not the
meaning of the word on the button.**

The apparatus is large and, within its perimeter, excellent:

| Guard class | Checks | Perimeter |
|---|---|---|
| Manifests + mirror tests | FE constant ⇄ BE constant | code ⇄ code |
| `BillingGateIlScanner` | a named method provably reaches the gate primitive | code ⇄ code |
| `EndpointReachabilityScanner` | an endpoint has a caller | code ⇄ code |
| `orderCountParity` / `orderCountContract` | one label prints one number on two screens | code ⇄ code |
| `gatedCapabilityClaims` | a marketing sentence names a tier the gate table agrees with | code ⇄ code |
| `route-reachability`, `link-crawl` | a route has an inbound link | code ⇄ code |

The exception proves it. `help-status-labels.test.ts:1-24` exists precisely because a help article
taught the opposite of what a badge means, and its header states the general case correctly:
*"No gate can know that a legitimate English word stopped being a status name."* It then solves that
for **status labels only**. Nothing generalised it.

Today's own commit said the same thing from the other side. `fd4c808` deleted three of CLAUDE.md's
five "non-negotiable" spatial signatures after finding they were never built, and explained why
nothing caught it: *"every guard in this repo scans `src/` for what is there rather than `docs/` for
what is claimed."*

**Where a claim's referent is outside the code, there is no verification path at all** — and that is
exactly the set of surfaces that lie. The corollary is the cheap test for the next instance: *point
at the thing that would have to change for this sentence to become false, and ask whether it lives
in this repository.* If it does not, the sentence is unguarded by construction.

Two special cases of the same shape recur often enough to name:

- **Absence renders as favourable.** An empty result set, a check that could not run, and a check
  that ran and passed are the same green — P0-2 and P0-3, plus the test-pack legs at
  `SupplierConnectionService.cs:648`/`:665`, which pass on `OrderCount == 0`.
- **The fix for one unverified claim creates the next one.** P0-4 was written into `plans.ts` by the
  same edit that repaired the 2026-08-06 audit-bullet incident, six lines below its own post-mortem.
  P0-1 survived a packet that landed *today* to fix the sentence beside it.

# Capability Truth Ledger

**Purpose.** Replace the periodic capability audit with a build error. A prose matrix rots between audits; this ledger is the single source that in-app copy, marketing copy and CI all read from.

**Precedent that already works — with one correction to how it works.** `FE/src/lib/marketing/format-catalog.ts` derives `/formats` and the landing-page counts from the typed rows in `FE/src/lib/standards/catalog.ts`, and an unknown id **does** fail the build. The mechanism is not what this plan previously claimed:

- The throw is at `format-catalog.ts:45` — `if (!entry) throw new Error(...)`.
- It reaches the build because `parseStatus()` is called at **module-init scope** inside the `IMPORT_FORMATS` literal (`format-catalog.ts:71-75`), and that module is imported by two prerendered pages — one Server Component (`src/app/(marketing)/formats/page.tsx:10`) and one Client Component that still prerenders (`src/app/(home)/page.tsx:17-20`, which is `"use client"` at `:1`). `next build` evaluates the module, so the throw fails the build. What runs it: **FE** `.github/workflows/ci.yml:74` (`bun run build`).
- **`tsc --noEmit` does NOT catch it.** `parseStatus(catalogId: string)` takes a bare `string`, not a union of catalog ids (`format-catalog.ts:42`). The typecheck step (**FE** `ci.yml:155`) is not the guard.
- **No test pins the throw, though one incidentally trips it.** Zero hits for `parseStatus` or `unknown standards catalog id` across `*.test.ts(x)` — delete the `throw`, return a default, and nothing goes red. A typo'd id *does* also fail `bun run test` (**FE** `ci.yml:110`) because `gatedCapabilityClaims.test.ts:6` imports the module and ES-module evaluation runs `:71-75`. That is a side effect of an import, not a pin.
- **Scope limit:** the guard fires on the `id` argument only. A wrong `name`, `note`, or a wrong `parse:` level in `standards/catalog.ts` renders a silently wrong badge. It also covers `IMPORT_FORMATS` only — `OUTPUT_FORMATS` (`format-catalog.ts:94-102`) is seven hardcoded literals with no derivation at all, which is exactly where the outbound over-claim below slipped through.

**Target implementation (`WP-40`) — NOT BUILT.** `FE/src/lib/capability-ledger.ts` does not exist: zero hits for `capability-ledger` / `capabilityLedger` / `CapabilityLedger` across `src/`, `scripts/` and `.github/`. **Nothing carries this document's schema** — no typed row with `documented` / `exposed` / `selfService` / `liveProven` columns, and therefore no check that fails when copy claims a capability with no row. The frontend does have two genuinely adjacent mechanisms, and the honest statement is that they cover *different* claim surfaces rather than this one: `standards/catalog.ts:35,40-56,74` is a typed capability-row table (`parse` / `transform` / `conformance` levels), and `legalCommitments.test.tsx:841-854` is a coverage guard that fails when a public page has no row in `PUBLIC_PAGES` (`:456`) and no reasoned exclusion (`:766`). `gatedCapabilityClaims.test.ts` checks **tier** correctness against a hand-typed mirror. None of the three can fail on "this sentence claims a capability nothing implements". This document is therefore still prose, and still rots. **Building the typed constant remains open work; this revision only re-derives the content.**

## Schema

| Field | Meaning |
|---|---|
| `id` | stable kebab id, referenced by copy |
| `claim` | the sentence a customer may read |
| `documented` | a help article or marketing page describes it |
| `implemented` | code exists that does it — **name the type and method** |
| `exposed` | a customer can reach it in the UI — **name the route** |
| `selfService` | a customer can configure and use it with no founder involvement |
| `tested` | a test that would go RED if it broke — **name it** |
| `liveProven` | proven on production — **evidence link required**: order id, attempt id, receiver capture, or dated QA doc |
| `honestLabel` | the in-product wording when any column is false |

**Rule:** `liveProven` without an evidence link fails CI. `exposed && !selfService` must carry an `honestLabel`.

**Sharpening to the `tested` rule, earned since the 2026-07-27 baseline.** The old rule said "an env-gated silent return is NOT a test". That is right but now too blunt — the repo has three distinct shapes and they are not equivalent:

| Shape | Runs on CI? | Counts as `tested`? |
|---|---|---|
| Bare `if (…) return;` inside the test body | Reports `Passed` while asserting nothing | **NO.** This is the `Live_ImapIngress` defect — dead since `de4ea0e`, green for two and a half weeks (`05-PROGRESS.md:919`, `:3364`). Now banned by `VacuousTestPassScanner` (five rules, `05-PROGRESS.md:3370`) |
| `[DockerRequiredFact]` / `[DockerRequiredTheory]` | **YES** — a declared xUnit `Skip` set in the attribute ctor (`ProcuLink.Api.Tests/Integration/EndToEndPipelineTests.cs:366-372`); `ubuntu-latest` has Docker, and CI run `30695203087` shows the Testcontainers connect plus per-cell `Passed` lines *(external)* | **YES** |
| `[EnvironmentGatedFact]` behind a `PROCULINK_LIVE_*` opt-in | **NO** — zero hits for those variables in `.github/workflows/**` | **NO.** Collected and skipped, forever |

CI runs `dotnet test ProcuLink.slnx` with **no `--filter`** (**BE** `ci.yml:70`) and fails on any skip with an empty reason (**BE** `ci.yml:83-110`). So the distinction is legible, not silent.

**Two `ci.yml` files exist.** Every workflow citation below is prefixed **BE** (`ProcuLink/.github/workflows/`) or **FE** (`project-proculink/.github/workflows/`). They are different files with different line numbers.

**Provenance labels used below.** `code` = re-derivable from these two repos. `vendor` = a supplier's documented behaviour, true but not checkable here (SSH.NET's default host-key trust, Railway's SMTP port blocking, Postmark's US-only policy). `external` = a CI run id or a production observation, not re-derivable from a checkout. `plan` = a `05-PROGRESS.md` citation, which is this plan's own record and therefore **not independent evidence** — it records that someone checked, not the check.

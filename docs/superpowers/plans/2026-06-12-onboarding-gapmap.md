## PART 3 — CONSTRAINTS ON ANY DESIGN

1. **One-great-experience rule (binding):** no novice/expert toggles, no localStorage user-mode flags; smart defaults + progressive disclosure + Cmd+K. Wizard-style flows ONLY for first-time-only paths (`docs/design-system/00-agent-quick-brief.md:93-95, 125-129`).
2. **Offer⇔works (founder rule, binding):** every control does what it says or is removed/relabeled — no dead deep-links, no claimed-but-absent buttons ("Resolve all"), no format lists diverging from BE whitelists; conservative capability copy (`/library/standards` is SoT). Never imply sent when only generated — explicit `ready_to_deliver/delivering/delivered/delivery_failed`; never equate HTTP 200 with supplier acceptance (north-star :116-118).
3. **Design system (`docs/design-system/11-unified-page-rules.md`):** compose `PageShell`/`PageHeader`/`Card`/`MobileListRow`/`Button`/`UnifiedStatusBadge` + shared `EmptyState`/`BridgeLoader` only; primary action = brand-green `#2E8E3A`; limes `#28C55E/#1DAF50/#1AAF50` banned; zero hex literals in pages (tokens only); Tailwind breakpoints only; `--tap-min: 44px`; ≥16px mobile inputs; respect `prefers-reduced-motion`. AI violet reserved for AI suggestions with visible confidence + Accept/Edit/Reject.
4. **Vocabulary:** bridge/dock/crossing PURGED from user copy (→ Dashboard/Suppliers/Buyers/Deliveries/"send to supplier") — do NOT copy `07-content.md` microcopy (stale); all Supplier↔Customer nouns through `useOrderDirection` per org direction. Five-stage journey Parse→Normalize→Validate→Transform→Deliver is the canonical mental model.
5. **North-star alignment (active plan, V-sequence governs):** onboarding orients toward creating/testing/publishing a versioned **connection** (V1), surfaces test-before-publish as the safety story (V2), keeps Scriban behind the visual map (V3), and frames the operator's day exception-first — "what's wrong, why, what do I do, will it remember, did the supplier accept" (V6). Topology = overview, not work queue. Archived Group-L scope (industry templates, magic-mapping hardening) is NOT the plan.
6. **Analytics:** reuse existing events (`wizard_opened/step_completed/dismissed`, `sample_order_started`, `welcome_viewed`, `help_slideover_opened`, `watch_demo_started`; BE firsts are idempotent and PostHog-only). Funnel events are NOT FE-readable — checklist state must come from extending `GET /api/onboarding/status` (add flags/counts + `IsSample` exclusion, G5), not from analytics.
7. **Existing BE contracts to build on (don't rebuild):** onboarding/status, sample-order, template list/apply/test, source-columns, catalog import, delivery-config GET-204 probe + test-fire, schema inference. Catalog import is file-only (CSV/XLSX); Erply/Directo template columns carry an unverified caveat — keep their "check against your export" disclaimer.
8. **Tech:** bun only; App Router; Server Components by default; TanStack Query in Client Components (gate on `isApiMockMode || clerkReady`); all API calls via `src/lib/api-client.ts`; no `useEffect` fetching; org-scoped EF queries; Hangfire jobs idempotent; no raw SQL.
9. **External dependencies to design around, not on:** Clerk `/welcome` redirect, `NEXT_PUBLIC_BOOK_DEMO_URL`, walkthrough video URLs, PostHog keys are all pending founder config — surfaces gated on them must degrade gracefully (current book-demo banners render nothing; acceptable pattern). Adding a tour/coachmark library is a new-dependency decision (none installed today).
10. **Plan-limit honesty:** state Pilot's 1-supplier/20-order/14-day limits where relevant (wizard step 1, supplier add); sample order is quota-exempt and must STAY excluded from billing AND become excluded from onboarding-status (G5).

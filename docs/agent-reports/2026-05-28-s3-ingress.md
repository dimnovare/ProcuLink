## Design decisions

### Mirror of SftpIngressService
The implementation mirrors `SftpIngressService` and `SftpPollingJob` exactly —
same `AcceptedExtensions` set (`.csv`, `.xlsx`, `.pdf`, `.xml`, `.edi`), same
`Guid.Empty` placeholder for `supplierId` (see *Known limitations* below), same
per-file `SaveChangesAsync` cadence for crash safety.

### ETag-based deduplication
`ImportedS3Object` records `(OrgId, BucketName, ObjectKey, ETag)`.
On each poll:
- If no row exists for the key → import and insert.
- If a row exists **and** the ETag matches → skip (already imported, unchanged).
- If a row exists but the ETag differs → re-import (object was overwritten) and update the record.

S3 ETags are MD5 hashes for single-part uploads and composite hashes for
multipart uploads. They are not guaranteed to be stable across bucket copies,
but they are stable for the same key within the same account.

### IAmazonS3 injection approach
`S3IngressService` takes `IAmazonS3` directly in its constructor. It does **not**
construct its own `AmazonS3Client` because credentials are per-org (stored
encrypted in `S3IngressConfig`).

**Recommended DI wiring in the parent session:**

```csharp
// In ProcuLink.Worker/Program.cs (or wherever IS3IngressService is registered):
builder.Services.AddScoped<IS3IngressService>(sp =>
{
    // At registration time we do not know which org is being polled.
    // S3PollingJob calls PollAsync(orgId) per org; the service loads
    // the config from the DB and uses the INJECTED IAmazonS3.
    //
    // Option A — single shared S3 client (simplest; works for single-account setups):
    //   Register a singleton/scoped AmazonS3Client configured for the platform
    //   account. Each org's ingress config uses credentials that have been
    //   granted access to that org's bucket or prefix.
    //
    // Option B — per-org factory (multi-account / cross-account):
    //   Register IS3IngressService using a factory that creates a fresh
    //   AmazonS3Client with the org's decrypted AccessKeyId/SecretKey at
    //   invocation time. Because S3PollingJob already iterates per-org, the
    //   factory can receive the config from the DB and create the client inline
    //   inside PollAsync — but that requires moving client construction INTO the
    //   service, which breaks the current constructor contract.
    //
    // The current implementation assumes Option A or that the caller wraps
    // PollAsync in a per-org factory function. The constructor takes IAmazonS3
    // so the DI caller fully controls credential scope.

    var s3 = sp.GetRequiredService<IAmazonS3>();
    return new S3IngressService(
        sp.GetRequiredService<ProcuLinkDbContext>(),
        sp.GetRequiredService<IOrderService>(),
        sp.GetRequiredService<DeliveryEncryptionService>(),
        s3,
        sp.GetRequiredService<ILogger<S3IngressService>>());
});
```

For a simpler setup where all orgs share a platform S3/R2 account, register a
single `AmazonS3Client` as a singleton and inject it directly.

## DbContext additions needed

The new entities use `[Table("...")]` data annotations, matching the
`SftpIngressConfig`/`ImportedSftpFile` pattern. EF auto-discovers them via
`_db.Set<T>()` without explicit `DbSet<T>` properties.

**However**, for production Postgres (not InMemory), `OnModelCreating` must map
them to include the unique index on `ImportedS3Object`. Add to
`ProcuLink.Infrastructure/ProcuLinkDbContext.cs`:

```csharp
// ── s3_ingress_configs ─────────────────────────────────────────────────────
modelBuilder.Entity<S3IngressConfig>(b =>
{
    b.ToTable("s3_ingress_configs");
    b.HasKey(x => x.Id);
    b.Property(x => x.Id).HasColumnName("id");
    b.Property(x => x.OrgId).HasColumnName("org_id");
    b.Property(x => x.BucketName).HasColumnName("bucket_name").IsRequired();
    b.Property(x => x.KeyPrefix).HasColumnName("key_prefix").IsRequired();
    b.Property(x => x.Region).HasColumnName("region").IsRequired();
    b.Property(x => x.AccessKeyId).HasColumnName("access_key_id").IsRequired();
    b.Property(x => x.EncryptedSecretKey).HasColumnName("encrypted_secret_key").IsRequired();
    b.Property(x => x.IsEnabled).HasColumnName("is_enabled");
    b.Property(x => x.CreatedAt).HasColumnName("created_at").HasColumnType("timestamptz");
    b.Property(x => x.UpdatedAt).HasColumnName("updated_at").HasColumnType("timestamptz");
});

// ── imported_s3_objects ────────────────────────────────────────────────────
modelBuilder.Entity<ImportedS3Object>(b =>
{
    b.ToTable("imported_s3_objects");
    b.HasKey(x => x.Id);
    b.Property(x => x.Id).HasColumnName("id");
    b.Property(x => x.OrgId).HasColumnName("org_id");
    b.Property(x => x.BucketName).HasColumnName("bucket_name").IsRequired();
    b.Property(x => x.ObjectKey).HasColumnName("object_key").IsRequired();
    b.Property(x => x.ETag).HasColumnName("etag").IsRequired();
    b.Property(x => x.ImportedAt).HasColumnName("imported_at").HasColumnType("timestamptz");
    b.HasIndex(x => new { x.OrgId, x.BucketName, x.ObjectKey }).IsUnique();
});
```

```csharp
// 1. Register IAmazonS3 (shared platform account or per-org factory — see above)
builder.Services.AddSingleton<IAmazonS3>(sp =>
{
    var cfg = sp.GetRequiredService<IConfiguration>();
    var config = new AmazonS3Config
    {
        ServiceURL           = cfg["S3Ingress:ServiceUrl"] ?? "https://s3.amazonaws.com",
        ForcePathStyle       = true,
        AuthenticationRegion = cfg["S3Ingress:Region"] ?? "eu-west-1",
    };
    return new AmazonS3Client(
        cfg["S3Ingress:AccessKeyId"],
        cfg["S3Ingress:SecretAccessKey"],
        config);
});

// 2. Register IS3IngressService
builder.Services.AddScoped<IS3IngressService, S3IngressService>();

// 3. Register the Hangfire recurring job (every 5 minutes, matching SFTP/email cadence)
RecurringJob.AddOrUpdate<S3PollingJob>(
    "s3-polling",
    job => job.ExecuteAsync(CancellationToken.None),
    "*/5 * * * *");
```

## Known limitations

1. **No DefaultSupplierId on S3IngressConfig.** `CreateStubAsync` requires a
   `supplierId`. This implementation uses `Guid.Empty` as a placeholder — the
   same convention used by `SftpIngressService`. A follow-up should add a
   `DefaultSupplierId` column (nullable `Guid`) and plumb it through.

2. **Single IAmazonS3 instance injected.** The current DI wiring assumes all
   orgs share the same S3/R2 platform account, or that the DI registration
   creates per-org clients. True per-org credential isolation requires a factory
   pattern (see *IAmazonS3 injection approach* above).

3. **No billing gate.** `EmailPollingJob` checks `IBillingService.HasFeatureAsync`
   before polling each org. S3 polling currently skips this gate. Add a
   `BillingFeature.S3Ingestion` gate before shipping to production.

4. **No pagination for large buckets.** The service loops over paginated
   `ListObjectsV2Response` pages (via `IsTruncated`/`ContinuationToken`), but
   there is no max-objects-per-run cap. A very large bucket could cause a single
   poll run to take longer than the 5-minute Hangfire interval.

5. **GetObjectAsync uses string overload.** The `GetObjectAsync(bucket, key, ct)`
   overload is used for simplicity. For large files, prefer a streaming approach
   to avoid materialising the entire object in a `MemoryStream`. 

6. **No API endpoints for S3 ingress config CRUD.** Operator must configure
   `S3IngressConfig` rows directly in the database or via a future settings API.
